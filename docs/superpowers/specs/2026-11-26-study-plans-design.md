# 忙里偷题：学习计划独立进度设计

日期：2026-11-26
状态：已确认，待实现
范围：学习计划入口、按计划独立的复习会话与进度、复习队列重放缺陷修复

## 1. 背景

2026-11-26 在真实浏览器中实测「多个计划同时加入今日」，确认三个问题：

- **入口不可达**：底部「计划」标签在核心体验重设计（`5d19b9a`）中移除，设计上归入「我的」。但「我的」页在一个计划都没有时只显示「还没有训练计划」一行文字，不是链接；页面上没有任何通往计划页的入口，只能手敲 `#/plans`。
- **多个计划不会各自完成**：今日目标是各计划目标之和，计划页也各有进度条，但复习会话只取第一个加入今日的计划来决定拉题数量和题库范围。实测计划甲（题库甲，每天 3 题）与计划乙（题库乙，每天 2 题）同时加入今日，从今日页进入的一轮只有题库甲的 3 题，计划乙始终 `0/2`。
- **完成的会话会被重放**：做完一轮、返回今日、再点「继续今日复习」，第二轮没有向服务器请求题目，展示的是前端缓存里的旧队列。实测把重放的一轮也做完后，复习日志从 3 条变成 6 条，三道题的稳定性从 1 天被翻到 2 天，下次间隔从约 4 小时被拉到约 8 小时。每日进度因去重规则没有翻倍，但记忆状态被污染。

## 2. 已确认的产品决策

1. **每个学习计划独立管理、独立进度**：一轮复习只属于一个计划，计划之间互不干扰。
2. **计划范围保持现状**：一个计划绑定一个题库，或覆盖全部题库。
3. **界面名称统一为「学习计划」**，替换现有的「训练计划」。

## 3. 范围边界

### 本次包含

- 今日页按计划呈现今日要完成的学习计划，每个计划有自己的进度和入口。
- 复习会话绑定单个计划：拉题数量、题库范围和提交归属都跟随该计划。
- 「我的」页与今日页补上可见的学习计划入口。
- 修复复习队列重放缺陷，并补回归测试。
- 新增端到端测试覆盖「两个计划各完成一轮」。

### 本次不包含

- 按分类、标签或筛选条件定义计划。
- 「新学 N 题 + 复习 M 题」这类配比目标。
- 计划历史、连续打卡、提醒。
- 后端接口变更和管理端改动。

## 4. 交互设计

### 4.1 今日页

今日总览卡保持现状：`今日完成 x / 目标之和`、当前到期、新题、重学中、到期题不足提示。

**没有加入今日的计划**（自由模式，行为不变）：

```text
┌ 今日完成                         2 / 2 ┐
│ ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓ │
│ 5 当前到期   3 新题   0 重学中         │
│ [        继续今日复习        ]        │
│        制定学习计划 · 设定每日目标 →    │
└───────────────────────────────────────┘
```

链接文案随状态变化：一个计划都没有时是「制定学习计划 · 设定每日目标」；已有计划但都不在今日时是「管理学习计划」。

**有加入今日的计划**：总览卡不再放主按钮，下方新增「今日计划」区，每个计划一张卡片。

```text
今日计划                      管理计划 →
┌───────────────────────────────────────┐
│ 学习科学                               │
│ 学习科学题库 · 每天 10 题               │
│ ▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░             │
│ 今日 2 / 10 题              [ 继续 ]   │
└───────────────────────────────────────┘
┌───────────────────────────────────────┐
│ Python                                │
│ Python 题库 · 每天 5 题                │
│ ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓             │
│ 今日 5 / 5 题 · 已达成       [ 加练 ]  │
└───────────────────────────────────────┘
          不按计划，自由刷题 →
```

卡片规则：

- 未达成：主按钮「开始」（今日 0 题）或「继续」，进入 `#/review?plan=<id>`。
- 已达成：显示「已达成」文字标记（不只靠颜色），提供「加练」次操作，进入同一地址。
- 「管理计划」进入 `#/plans`；「不按计划，自由刷题」进入 `#/review`，让不在任何计划题库里的题目仍然可达。
- 计划接口失败时，总览卡退回自由模式主按钮，计划区显示失败原因和重试；不把失败显示成「没有计划」。

### 4.2 复习页

- `#/review?plan=<id>`：计划存在且在今日计划中，本轮绑定该计划。副标题显示计划名，完成页标题为「「计划名」这一轮完成了」。
- `#/review`：自由模式，一轮 20 题，不绑定计划。
- 计划不存在或不在今日计划中（例如过期书签）：按自由模式处理。

### 4.3 学习计划页与「我的」

- 计划页标题改为「学习计划」，说明文案点明「每个计划单独复习、单独计进度」；创建、加入今日、退出今日、删除的行为不变。
- 「我的 → 我的计划」在空态下提供「新建学习计划」链接，不再只有一行文字。

## 5. 技术设计

### 5.1 会话绑定计划

`useReviewSession(categoryId, bankId, planId)`：

- `planId` 指向今日计划中的某个计划时，`limit = max(1, daily_goal - today_done)`；已达成时取 20（加练）。
- 题库范围取 `plan.bank_id`；提交携带 `plan_id`，服务端既有的归属与范围校验保持不变。
- 不再隐式选择「第一个加入今日的计划」。没有 `planId` 就是自由模式。
- `limit` 上限按接口约束截到 100，避免每日目标超过 100 时请求被拒。
- 计算出的 `limit` 进入查询键，计划进度刷新后会以正确的数量重新拉题。

### 5.2 队列新鲜度（缺陷修复）

进入复习页后，只在同时满足以下条件时用拉取结果建立会话：

1. 本次挂载后发生过拉取（`isFetchedAfterMount`）；
2. 没有更新的请求在途（`isFetching` 为假）；
3. 本次拉取成功（`isError` 为假）；
4. 本次挂载尚未建立过会话，且没有恢复中的快照。

效果：缓存里的旧队列不会被当成新会话；后台刷新不会重置进行中的会话；刷新失败仍保留当前题并提示（既有行为）。

### 5.3 快照

- 进行中的会话照旧写入并恢复快照。
- 会话完成后清除快照，不再保存；读取时遇到「已完成」的快照（旧版本遗留）直接清除并视为没有快照。

### 5.4 今日页数据

今日页新增三个查询：`GET /plans`、`GET /plans/active`、`GET /questions/banks`（仅在有绑定题库的今日计划时启用）。后端接口不变。

## 6. 与既有约束的关系

- **服务端是唯一事实源**：计划进度、今日总览都来自接口；缓存只用于展示，不能重建一次已完成的复习。
- **失败必须可见**：计划加载失败有明确的错误与重试。
- **每日进度去重**：口径不变，仍是计划范围内当日首次完成的不同题目数。
- **快照最小化**：完成的会话不再占用快照。

## 7. 测试与验收

组件测试：

- 快照：已完成的会话不保存、不恢复。
- 复习页：缓存里有旧队列时重新进入会拉取新队列；`?plan=` 会话按计划剩余数量和题库拉题，提交带 `plan_id`。
- 今日页：今日计划逐个展示、各有进度和入口；没有今日计划时提供制定计划入口；计划加载失败可重试。
- 「我的」：空态有新建计划链接。计划页：标题为「学习计划」。

端到端测试：

- 两个计划各完成一轮：第二轮必须请求服务器而不是重放第一轮的题；每个计划的进度独立；复习日志没有重复。

回归：App 全量组件测试、后端全量测试、App 生产构建、核心 E2E。现有视觉基线为 win32 平台生成，在 Linux 上不作为本次验收门禁。

## 8. 风险与取舍

- 总览卡与计划卡片在只有一个计划时会显示两处进度。取舍：保持总览卡作为稳定的每日概览，计划卡片承担操作，布局不随计划数量跳动。
- 自由模式的作答按题库范围计入对应计划的进度（服务端既有口径）。这是既有行为，本次不改；「自由刷题」入口只是让它可达。
- 计划会话的目标是「完成今日目标」，不是「清空到期题」。到期题多于目标时，剩余部分由之后的日期承接。
