# 忙里偷题：科学记忆引擎与核心体验重设计

日期：2026-11-25
状态：已实现（2026-11-26 完成后端、组件、E2E 与三视口视觉验收）
范围：P0 复习可靠性、P1 记忆引擎与复习端核心体验

## 1. 背景与判断

当前工程已经具备题库、刷题、训练计划、统计、AI 讲题和后台管理等骨架，但尚未形成产品级体验：

- 材料导入和 AI 出题仍有占位接口，核心内容供应链未闭合。
- 复习提交失败会被静默忽略，用户可能误以为学习记录已经保存。
- 排期使用固定间隔倍数和日期粒度，不能支持短时重学或个性化记忆稳定性。
- 每日计划按日志条数计数，重复作答可能虚增进度。
- App 要求用户粘贴 API token，缺少首次引导、会话恢复和统一的异常反馈。
- 复习端主要由页面级代码和单个全局 CSS 文件构成，缺少可复用的产品组件与明确的交互状态。
- 后端已有自动化测试，但前端没有组件测试和端到端测试。

本设计不推倒重写。保留 FastAPI、SQLModel、React、PWA 和自部署架构，优先修复学习记录可靠性，再建立可解释的记忆模型和移动端核心体验。

## 2. 产品原则

1. **学习记录可信**：任何已展示的进度都必须已经成功保存；失败不得静默。
2. **复习安排可解释**：用户可以知道为什么今天出现、下次何时出现。
3. **科学表述克制**：艾宾浩斯遗忘规律是模型基础，不承诺“保证记住”。
4. **专注单一任务**：复习页只服务当前一道题，AI、出处和编辑不得破坏节奏。
5. **移动端优先**：360px 小屏、单手操作、安全区和弱网是一等约束。
6. **服务端是唯一事实源**：本地缓存用于恢复和展示，不替代学习记录。

## 3. 范围边界

### 本期包含

- 可靠的复习提交、重试与刷新恢复。
- 分钟级 `due_at`、短时重学、个性化记忆稳定性和目标保持率。
- 今日、复习、题库、记忆洞察四个核心页面的重设计。
- 统一的基础组件、加载/空态/错误反馈和移动端适配。
- 数据库正式迁移、数据导出兼容和自动化测试。
- 管理端真实路由与按需加载仅做必要配套，不进行完整后台重设计。

### 本期不包含

- FSRS 的完整实现。
- 离线题包和离线作答。
- PDF、图片、网页等多格式材料导入。
- Anki 导出、MCP、原生 App。
- 多租户计费、公开注册和复杂组织权限。

## 5. 科学记忆引擎

### 5.1 模型定位

第一版采用透明的指数遗忘近似：

```text
R(t) = exp(-t / S)
```

- `R`：经过时间 `t` 后的预计保持率。
- `S`：该用户对该题的记忆稳定性，单位为天。
- 每次真实回答根据评分更新 `S`，因此不同题目和不同用户会形成不同排期。
- 该公式是可解释的初始近似，不宣称精确模拟人脑；后续可以根据真实记录校准或替换为 FSRS。

默认目标保持率为 `0.85`。下次间隔为：

```text
interval = -S × ln(target_retention)
```

前端显示的是由该模型得到的预计时间，而不是写死的宣传文案。

### 5.2 四档评分规则

| 评分 | 含义 | 稳定性更新 | 下一次出现 |
|---|---|---|---|
| again | 没有回忆起来 | `S = max(0.1, S × 0.5)`，记录一次遗忘 | 10 分钟后重学，并加入本次会话末尾 |
| hard | 回忆困难 | `S × 1.2` | 按目标保持率计算，间隔不得小于当前间隔 |
| good | 正常回忆 | `S × 2.0` | 按目标保持率计算 |
| easy | 轻松回忆 | `S × 2.8` | 按目标保持率计算 |

新题没有历史稳定性时，以首次评分初始化：

- `again`：进入 10 分钟重学，不产生成熟间隔。
- `hard`：`S = 0.5` 天。
- `good`：`S = 1` 天。
- `easy`：`S = 2` 天。

所有间隔设置安全边界，最短 10 分钟，最长 365 天。初始参数是产品默认值，后续调整必须保留算法版本，避免旧记录无法解释。

### 5.3 学习状态

每题保留：

- `status`：`new / learning / review / relearning`，不再仅用 21 天阈值定义全部状态。
- `due_at`：带时区的下次到期时间。
- `stability_days`：个人对此题的记忆稳定性。
- `interval_minutes`：最近一次实际排期间隔。
- `reps`、`lapses`、`last_rating`、`last_reviewed_at`。
- `algorithm_version`：解释历史排期使用的规则版本。
- `(user_id, question_id)` 数据库唯一约束，防止并发产生重复状态。

“已掌握”是展示标签：只有进入稳定复习阶段且当前间隔达到 21 天才显示，不再是算法状态机的唯一依据。

### 5.4 会话内重学

- 答错后服务端安排 10 分钟重学，客户端同时把题放入当前会话末尾。
- 如果还有其他到期题，先继续其他题；没有时显示“立即重学”或“稍后再来”。
- 重学再次答错只增加一次实际复习日志，不增加每日目标的 unique 完成数。
- 会话快照保存当前队列、当前题、已输入答案、提交用 `client_id` 和重学队列。
- 快照仅保存当前复习所需的题目、答案和状态，退出登录时清除。

### 5.5 每日目标口径

- 每日进度按“计划范围内当日首次完成的不同题目数”计算。
- 重学、AI 求助和重复回写不重复增加目标进度。
- 复习提交增加可选 `plan_id`，服务端校验计划归属和题库范围。
- 当前启用的计划保存到服务端用户偏好，避免换浏览器后状态变化。
- 到期题不足时明确显示“到期题不足”，不得伪造成用户已经答满目标。

## 6. 复习可靠性设计

### 6.1 复习提交状态机

```text
answering → rating → submitting → submitted → next
                         │
                         └→ retrying / failed
```

- 进入 `submitting` 后禁用评分和下一题按钮。
- 只有服务端确认成功才进入 `submitted`。
- 网络失败保留当前题、答案和评分，展示内联错误及重试按钮。
- 重试使用原 `client_id`，不得生成新键。
- 重复点击、刷新或浏览器重发不能产生重复日志或重复推进排期。
- 401 跳转登录前保留会话快照；重新登录后回到当前题。

### 6.2 队列与并发

- 拉取新队列时排除当前会话已经提交成功的题。
- 同一客户端只允许一个提交请求占用当前题。
- 服务端通过 `client_id` 唯一约束和事务处理重复提交。
- 队列拉取失败保留旧队列，不用空数组伪装成“今日完成”。

### 6.3 AI 与辅助操作

- AI 讲题失败不阻塞复习提交和下一题。
- 题目标记、编辑和删除必须说明对当前会话及历史记录的影响。
- 已有学习记录的题目只能暂停，不能物理删除；无学习记录的题目可以直接删除，避免历史统计和导出出现孤立日志。

## 7. 数据迁移与兼容

使用 Alembic 替代继续扩张的启动时补丁迁移：

1. 新增记忆状态字段和唯一约束。
2. 旧 `due_date` 转为当地日期 00:00，再保存为 UTC `due_at`。
3. 旧 `interval_days` 转为 `interval_minutes`。
4. 使用旧间隔反推初始稳定性：`S = interval_days / -ln(0.85)`；无间隔的新题使用默认初始值。
5. 从最近一条复习日志恢复 `last_reviewed_at` 和 `last_rating`。
6. 旧 `learning / mastered` 映射到 `learning / review`，重学状态由新规则产生。
7. 导出格式升级版本，同时保留旧版本导入适配器。
8. 迁移和导入均为事务操作；失败不得留下半份状态。

## 8. 前端信息架构

底部主导航调整为：

- **今日**：今日任务和复习入口。
- **题库**：题库、分类、题目与待确认内容。
- **导入**：手工录题，后续承接 Markdown 和 AI 生成。
- **我的**：账户、计划、设置、数据管理；记忆洞察从今日进入。

复习页进入专注模式后隐藏底部导航，减少误触和视觉干扰。

规则：

- “保持率”来自实际复习日志，不把模型预测值冒充真实结果。

## 10. 视觉与组件方案

复习端保留当前“纸张、墨色、暖色点缀”的品牌方向，但建立完整组件体系，而不是继续扩张全局 CSS：

- `Button`：主/次/危险/文字按钮，加载、禁用和触控状态。
- `Card`、`Progress`、`Chip`：信息展示。
- `Sheet`、`Dialog`、`Toast`：分层反馈，不用原生 `alert`。
- `Skeleton`、`EmptyState`、`ErrorState`：所有异步页面统一状态。
- `Field`、`Select`、`Editor`：校验、帮助、错误和未保存状态。
- `BottomNav`、`AppHeader`、`ReviewRatingBar`：核心导航和复习操作。

实现使用设计令牌 + CSS Modules；动画保持 150–250ms，并尊重 `prefers-reduced-motion`。移动端不引入 Ant Design，避免把后台视觉语言直接搬到复习端。

管理端继续使用 Ant Design：

- 页面改为真实路由，刷新后保持位置。
- Markdown 编辑器、账户和数据页按需加载。
- 与 App 共用颜色、字体和 API 错误语义，但不要求共用全部组件。

## 11. 状态管理与 API 契约

- TanStack Query 管理题库、计划、统计等服务端数据。
- `ReviewSession` 使用 `useReducer` 实现显式状态机，不再依赖多个可相互失配的 `ref`。
- 从 FastAPI OpenAPI 生成 TypeScript 契约类型，CI 检查类型漂移。
- API 错误区分：网络错误、鉴权过期、校验失败、冲突、服务异常。
- 写操作返回真实状态；前端不得仅依据本地推测更新“已保存”事实。
- 评分响应返回新的 `due_at`、预计间隔和算法版本，供界面解释。

## 12. 测试与验收

### 后端

- 指数模型、四档评分、初始稳定性、最短/最长间隔的确定性单元测试。
- 新题、重学、连续遗忘、时区跨日和夏令时边界测试。
- `client_id` 并发重放不重复写日志、不重复推进排期。
- `(user_id, question_id)` 唯一约束和事务回滚测试。
- 每日目标按不同题目计数，重学不重复计数。
- 旧库迁移、旧导出导入、新导出往返测试。

### 前端

- 复习状态机覆盖成功、失败、重试、刷新恢复和 401 恢复。
- 评分按钮在提交中不可重复点击。
- 今日、题库和洞察的加载、空态、错误态组件测试。
- 360px、768px、1440px 的 Playwright 截图回归。
- 一条核心 E2E：登录 → 复习 → 网络失败 → 重试 → 下一题 → 刷新恢复。

### 产品验收

- 任何已显示的完成进度都能在服务端查到。
- 答错题能按设计进入短时重学，刷新后不丢失当前会话。
- 用户能查看每题下次复习时间及评分如何影响排期。
- 360px 屏幕无横向溢出，核心操作可单手完成。
- 首次用户无需 CLI 或粘贴 token，即可登录、使用示例题并完成一次复习。
- 统计数字有明确口径和样本量，不展示伪精确结论。

## 13. 实施顺序

1. 建立复习可靠性测试，修复提交、重试和队列问题。
2. 引入 Alembic 和新记忆状态，完成旧数据迁移与导出兼容。
3. 实现记忆引擎和分钟级到期队列，保持旧 API 的过渡适配。
4. 重做复习会话状态机和专注复习页。
5. 建立组件体系，依次完成今日、题库、记忆洞察。
6. 完成账号登录、首次引导、示例数据和设置。
7. 运行全量测试、E2E、移动端截图与升级恢复验证。
8. 核心记忆体验稳定后，再进入 Markdown/AI 出题的内容闭环设计。

## 14. 成功指标

默认不接入第三方行为分析，优先从已有学习记录计算：

- 复习提交失败率与重试成功率。
